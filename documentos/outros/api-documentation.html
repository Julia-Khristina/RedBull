Documentação da API - Red Bull 24 Horas

Documento organizado no formato de referência técnica inspirado em OAS, com recursos, formatos de midia, corpos de requisição, respostas, autenticação e exemplos.

3.6 WebAPI and Endpoints

A API do projeto Red Bull 24 Horas foi organizada por domínios de uso da aplicação: competições, equipes, atletas, administradores, checkpoints, ranking, exportação e relatórios. Os endpoints listados como implementados correspondem ao conjunto de rotas registrado no backend atual. Autenticação, OCR, inconsistências e relatórios permanecem documentados como funcionalidades planejadas pelo WAD.

Media type: application/json Formato de erro: JSON Implemented Planned

Authentication

As rotas administrativas devem considerar autenticação por token quando a camada de segurança estiver integrada. O formato esperado e: 

Authorization: Bearer <token>
Content-Type: application/json

Resposta padrão de erro

{
  "message": "Descrição do erro"
}

Códigos de saída HTTP

Código Uso esperado Formato de resposta
200 OK Consulta, listagem, atualização ou operação concluida com retorno no corpo da resposta. JSON com objeto ou lista de objetos.
201 Created Recurso criado com sucesso por uma requisição POST. JSON com o recurso criado e seu identificador.
204 No Content Exclusao ou operação concluida sem corpo de resposta. Sem body.
400 Bad Request Payload inválido, parametro ausente ou parametro numerico em formato incorreto. { "message": "Descrição do erro" }
401 Unauthorized Token ausente, inválido ou expirado quando a autenticação estiver habilitada. { "message": "Token inválido ou expirado" }
404 Not Found Recurso solicitado não encontrado. { "message": "Recurso não encontrado" }
409 Conflict Conflito de regra de negócio, como duplicidade de dado unico. { "message": "Conflito ao processar recurso" }
422 Unprocessable Entity Dados sintaticamente validos, mas inconsistentes com a regra de negócio. { "message": "Dados inconsistentes" }
500 Internal Server Error Falha inesperada na API ou na integracao com o banco. { "message": "Erro interno do servidor" }

3.6.1 Competition Routes

As rotas de competição permitem criar, listar, consultar, atualizar, encerrar e remover competições. Elas atendem principalmente aos requisitos RF001, RF002 e RF012.

Metodo Endpoint Status Descrição RF/RN
POST /competitions Implemented Cria uma competição com nome, data e endereco. RF001, RF002, RN03, RN18
GET /competitions Implemented Lista as competições cadastradas. RF002, RN18
GET /competitions/:id Implemented Consulta uma competição específica pelo identificador. RF002, RN18
PUT /competitions/:id Implemented Atualiza os dados cadastrais de uma competição. RF002, RN18
PATCH /competitions/:id Implemented Encerra a competição e bloqueia novos registros operacionais. RF012, RN14
DELETE /competitions/:id Implemented Remove uma competição existente. RF002, RN18

Request body - POST/PUT

{
  "nome": "Red Bull 24h Sao Paulo",
  "data": "2026-06-15",
  "endereco": "Sao Paulo - SP"
}

Response - 201 Created

{
  "id": 1,
  "nome": "Red Bull 24h Sao Paulo",
  "data": "2026-06-15",
  "endereco": "Sao Paulo - SP",
  "status": "não iniciado",
  "criado_em": "2026-05-28T10:00:00.000Z"
}

Saídas da requisição

Operacao Sucesso Erros esperados Observação
POST /competitions 201 Created 400, 409, 500 Retorna a competição criada. Campos obrigatorios: nome, data, endereco.
GET /competitions 200 OK 500 Retorna uma lista; se não houver registros, retorna array vazio.
GET /competitions/:id 200 OK 400, 404, 500 Retorna uma competição ou erro se o ID for inválido/inexistente.
PUT /competitions/:id 200 OK 400, 404, 409, 500 Retorna a competição atualizada.
PATCH /competitions/:id 200 OK 400, 404, 422, 500 Retorna a competição com status de encerramento.
DELETE /competitions/:id 204 No Content 400, 404, 500 Nao retorna corpo em caso de sucesso.
